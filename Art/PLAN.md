# 开发计划

《看谁先上车》复刻工程。目标是把原作的**玩法、关卡、观感**尽量还原到能玩的程度，
再补上体力、广告、道具这些外围系统。

- 美术/配置来源：`Art/`（微信小游戏缓存快照，只做本地对照，**不随包发布**）
- 参考实现：`Assets/Scripts/Game/{Common,Client}`
- 进度同步：每完成一块就更新本文件和 `README.md`

---

## 三、建议的下一步

按性价比排：

1. **车坐满才走 + 6 辆上限** —— 这是玩法核心，直接决定手感对不对
2. **掉落动画** —— 观感，但改动不大
3. **体力 + 广告** —— 商业化闭环，也是"完整"的分水岭

## 四、技术债

| 问题 | 影响 | 计划 |
|---|---|---|
| `GameView` 1100+ 行 | 改布局难 | 拆成 Board / Bus / Hud 三个视图 |
| 每次刷新重建全部 Image | 发车时 GC 抖动 | 换对象池，只更新位置和显隐 |
| 关卡一关一个 JSON | 2000 关难管 | 合并成大文件或 Addressables |
| 编辑器截图工具手搓 UI | 和运行时略有差异 | 抽公共的视图工厂 |
| 8 色调色板 | 部分关卡被跳过 | 扩到 16–18 色 |

## 五、约束与风险

1. `Art/` 里的素材和配置版权属于原作者，只用于本地对照，发布包不能带；
2. `.wxapkg` 是 `V1MMWX` 加密的，代码解不出来，规则只能靠配置反推；
3. 关卡 JSON 走 `Assets/Res` + libra `ResMgr`，编辑器可用，**真机需要资源包流程**；
4. 单次会话上下文有限，每轮结束都会提交并同步本文件，方便换会话接着做。
